# N14 图灵机 Max 资源更新设计

- 版本：N14
- 状态：实施中
- 实施策略：沿用游戏大厅当前的资源适配、内容编号、签名目录和历史保留机制；仅对图灵机资源执行兼容迁移。

## 设计目标

1. 将上游 Max 不限步数功能引入大厅资源。
2. 保持旧版 reader 接受已有基础项目格式。
3. 将完整新版项目与旧版兼容视图分开保护，避免旧 writer 丢弃新版状态。
4. 仅由用户显式选择有限兼容值；任何自动写回都不得覆盖完整原档。
5. 使用可复核的来源 SHA、构建输入、产物 SHA 和发行历史完成交付。

## 存档边界

新版完整项目保留上游的 `maxSteps: null`、未知字段及原始文本。为旧版生成的兼容视图只能沿用完整档里已明确记录的既有有限步数；不允许用户临时输入一个有限值来冒充 Max。若导入的 Max 完整档没有可信的既有有限设置，新版仍可运行和完整导出，但不得新建或改写旧版镜像；如现有旧镜像存在则保持原字节，直到用户明确恢复有限模式。

完整文件将兼容视图和完整原文绑定；旧 reader 只读取有限视图，忽略扩展字段。图灵机存档是一份项目对象而非带多个记录 ID 的集合：冲突合并以该项目存储键作为稳定身份，仅将旧 reader 可读的已知字段合并到同一完整项目，保留完整档的未知字段。用户选择应用旧版编辑后，明确以实际有限 `maxSteps` 结束 Max 模式；选择恢复完整档时，旧版修改原文作为历史保留；取消时两份源数据不变。

已有大厅适配层及冻结的旧 reader 已覆盖 Max 与旧版有限字段映射；其任意显式兼容值提示不符合现行存档规范，必须改为只沿用已记录的有限配置。本轮先以真实 `ffca` 来源验证 UI 接入标记，再调整输入证明、适配代码与冲突合并；如上游变化破坏既有边界，暂停发布并先修复、独立审阅兼容层。

## 构建和发布边界

- 原始仓库只读。使用归档 bundle 在独立检出目录构建。
- 每个资源只读取锁定 SHA；来源证明列出完整输入和输出 SHA。
- 资源候选双次构建一致后，只为图灵机提升 contentCode；其余游戏 ZIP 字节及内容编号保持不变。
- 上传图灵机 ZIP 后再发布新签名目录；保留旧签名目录和 ZIP 历史。
- 不构建、不签署、不上传 Android APK。
