# 网页版离线与本地存档：需求与测试用例

状态：PENDING。范围为已发布 GitHub Pages 目录中的 28 款游戏；不修改原游戏仓库、Android APK 或签名资源目录。用户要求断网重开大厅和每个游戏、保存已有进度、管理本地存档并逐款验证。首次准备需联网；首次准备未成功不得显示可离线。

## 需求

- 离线准备覆盖大厅、目录、所有 28 款游戏入口及其完整同源资源（含 Worker、WASM 和字体），显示准备进度、完成或失败；网络中断、存储不足、文件损坏或浏览器不支持时明确提示，并保留原可用版本与存档。
- 前台可查看离线状态，断网后关闭并重新打开已准备的大厅仍能选择并进入游戏。更新须完整验证后切换；新版本准备失败不能破坏旧离线版本。后台、重复操作和多标签不得造成资源混版。
- 各游戏的持久进度应在退出重入、断网重开后保留，现有键名、游戏隔离和存档格式保持兼容。盘点发现学习小机器、尺规工坊、傅里叶绘图、熄灯矩阵缺少持久化，需逐项适配并验证真实用户操作；其他游戏必须逐项确认，不能用测试哨兵键代替实际进度。
- 大厅提供本地存档查看和可携带的导出、手动导入；覆盖前明确告知并保留可恢复的原数据，取消或失败不破坏原存档。不得自动导入或覆盖已有进度；IndexedDB 数据、不同游戏隔离及异步失败须纳入设计。现有游戏自带导入导出继续可用。
- 浏览器可能清理网站数据、配额不足或被用户清除；申请持久存储并如实显示，提供用户可下载备份，但不能承诺浏览器存储或设备损坏绝不会丢失。网页、安卓和不同设备存档不自动互通。

## 验收

U01 首次在线准备完成后，断网重启浏览器上下文，离线打开大厅并逐款进入 28 个入口、返回大厅，无网络依赖。U02 资源缺失、中断和配额不足时不显示成功，旧版本仍可使用。U03 每款记录一次有意义的游戏编辑/操作，退出重入及断网重启后验证真实状态；不具备保存条件须明确列出并处理。U04 整体和单游戏备份包含对应持久存储，恢复前后真实数据一致，取消、损坏、配额及其他游戏数据不受影响。U05 更新失败、两个标签页、游戏 Worker、路径和独立 origin 不产生跨游戏污染。U06 Chromium 桌面与移动视口执行；Safari/iPad 若无设备只能如实列为未验。
