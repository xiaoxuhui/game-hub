# 网页版离线与存档管理设计

状态：PENDING。使用原有 GitHub Pages 路径，静态部署，不依赖本机服务或后端。保持当前线上资源和用户现有 localStorage / IndexedDB 前缀，不迁移或清空已有保存数据。

## 资源离线

构建时根据已验签来源和实际发布文件生成包含路径、字节数与 SHA-256 的版本清单。Service Worker 在新版本独立缓存内下载并验证完整清单，全部成功才可激活；失败丢弃未完成候选，旧版本保持。页面检测支持、权限与空间，展示准备中、已就绪和失败；仅缓存完整版本可以被称为离线可用。离线时以已验证缓存提供主页、目录、游戏资源及 Worker；未知路径和外站请求不伪造成功。更新遵循浏览器 Service Worker 生命周期，避免未经确认切换正在使用的版本。

## 存档

现有游戏存储键保留 `game-hub-pages.v1.<游戏ID>.`，不得修改旧数据；发现 IndexedDB 的 `pixel-frame` 和 `ai-racing-lab` 必须支持真实数据的完整导出/恢复，其他动态数据库与 Worker 需扫描并验证。存档只在用户明确操作时从受限文件导入，事先校验格式、游戏 ID、大小、对象类型和范围；不得写入其他网站或其他游戏。恢复前须保留原数据，出现不支持的数据类型或无法安全回滚时明确拒绝，绝不静默丢失或部分替换。后台自动恢复导入不允许。

四个当前没有本地持久化的游戏使用独立、可追溯的网页适配器补充其真实编辑状态，优先保留原有交互和规则；适配后代码差异及摘要登记。浏览器缓存和存档分离，更新或清理离线资源不得清除存档。持久化权限与用户文件备份的局限在界面提示。

## 验证边界

每款游戏逐一记录保存对象、真实操作、重启与离线结果；对缺少状态或训练为纯临时过程的情形不得造假。测试使用独立浏览器配置和临时目录，不访问用户现有存档。桌面 Chromium 和移动视口测试不代表 iPad 实机测试；浏览器强行回收和硬件损坏需通过独立备份降低风险。
