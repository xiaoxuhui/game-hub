# 网页资源签名合同 v1

- 状态：PENDING；W2.0b实现前合同，当前没有启用签名目录或离线安装入口。
- 范围：网页独立通道，不修改Android v1/v2目录、内容编号、签名封装或发行资产。

## 1. 封装与信任入口

沿用现有envelopeVersion=1的四个严格字段：envelopeVersion、keyId、payloadBase64、signatureBase64。UTF8封装最多8MiB、解码payload最多4MiB；拒绝未知/缺字段、重复转义键、非法UTF8/路径/非规范整数和非规范Base64。验签使用payloadBase64解出的**原始字节**，不重新序列化后验签。RSA3072、RSASSA-PKCS1-v1_5、SHA-256，签名384字节，SPKI公钥由受审大厅调用端固定，不从目录、URL或用户输入选择。

纯函数接收调用端提供的公钥字节及预期keyId供测试/不同构建复用；这不是面向用户的可配置key入口，也不授予Cache/IDB安装状态。正式受控入口随后必须封装固定信任身份。测试只在Node内存生成密钥，浏览器只接收测试公钥/签名向量，私钥不写入源码或网页产物。

## 2. 网页payload

严格字段：schemaVersion=1、channel=game-hub-web-v1、catalogSequence、issuedAt、expiresAt、origin、basePath、shellVersion、sourceCommit、games。

- catalogSequence为1至2^63-1的规范十进制字符串，独立于APK通道。
- issuedAt/expiresAt为带毫秒的规范UTC ISO字符串，时长>0且最多90天。新的检查/安装授权须未过期，签发时间最多容忍5分钟超前；now必须是有效安全整数时间。已接受本机历史与时钟出现超过5分钟倒退时拒绝新授权。
- origin必须是无路径/凭据/查询/片段的规范HTTPS origin；本地测试允许HTTP loopback。必须等于调用端当前预期origin，basePath也必须精确匹配规范绝对目录。
- shellVersion是规范三段版本，不得低于当前壳或本机已接受历史；sourceCommit是网页候选完整40位公开提交SHA。
- games为1–32项，稳定ID唯一、来源/存储所有权无冲突。目录保留已接受历史的全部ID；不再可安装用available=false，不能靠删项绕过历史。

## 3. 每游戏严格字段

id、displayName、version、contentCode、digest、entryUrl、entryPage、category、iconKind、sourceRepository、sourceRevision、storage、sourceFiles、files、csp、available、adapterRevision、storageContract、webCapabilities、releaseNotes。

- 复用已审在线文件/来源身份校验：每份文件path/bytes/sha256/mime，完整文件树digest、入口的base/id/code/digest绑定，原始sourceFiles及适配产物中的source-proof身份一致；许可/入口必备。单文件20MiB、单游戏100MiB、最多2000文件，负零及非安全整数字节数拒绝。
- contentCode为正安全整数，独立于Android编号；sourceRepository是已支持的公开GitHub归属，sourceRevision/adapterRevision完整40位SHA。adapterRevision应由生产端固定为实际适配输入身份，文档/测试提交不自动改变游戏身份。
- storageContract固定为game-hub-web-save-v1，storage仍使用稳定keys/prefixes；同ID升级不自动变更所有权，变更需另行迁移合同。
- webCapabilities是无重复的已知能力集合：storage、files、worker、audio、microphone；microphone必须同时声明audio。未知能力不静默授权。
- csp必须匹配受审游戏CSP；iconKind只使用当前受审图标种类。available严格布尔，releaseNotes纯文本最多2000字符。

## 4. 本机历史与结果

验签成功仍只表明目录授权与身份有效，尚未验证文件下载或离线安装。返回深层冻结的目录与历史摘要；摘要绑定origin/base、channel、sequence、payload原字节SHA、壳版本、acceptedAt和全部游戏的编号/内容/描述/存储身份。

- sequence不得倒退；相同sequence只接受相同payload SHA，不接受换时间/资源后复用序号。
- 同ID编号不得倒退；同编号游戏身份必须相同，描述/来源/适配器/能力/文件变化都不能借同编号替换。存储所有权保持不变，新增ID不与旧ID冲突。
- 历史格式损坏/未知时拒绝新授权，不静默当首次检查。调用前复制/验证历史和key输入，验签等待期间外部修改不能替换预期历史。
- 首次没有历史、或者用户/浏览器清除全站数据时，纯合同无法凭空证明曾见过的水位；后续IDB/Cache修复路径必须区别数据重置与完整已有安装，不能从残留文件猜测信任。

历史已安装版本不因目录到期失效；其完整证明、缓存与会话引用验证在W2存储协调切片另行实现。本函数的过期拒绝专用于新检查/下载授权，不能被安装端当作“已保存”标记。生产端签署与公开原子部署仍由W3/W4分别验收。

## 5. 验收与依据

Node使用内存RSA测试身份；正例及错key/签名、原字节变化、重复键/UTF8/Base64、未知字段/通道、origin/base/路径、来源/文件树、有效期/时钟、序号/编号/身份倒退、历史损坏和等待期输入变更都须拒绝。三浏览器对相同签名向量使用真实WebCrypto，测试身份不写进产物。

实现API依据[W3C Web Cryptography API稳定建议标准](https://www.w3.org/TR/2017/REC-WebCryptoAPI-20170126/#rsassa-pkcs1)：SPKI导入和RSASSA-PKCS1-v1_5验签；应用层字段、预算和历史政策来自本仓已审网页设计，不把密码API本身当部署/存储原子性保证。
