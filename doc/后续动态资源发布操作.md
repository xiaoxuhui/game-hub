# 后续动态资源发布

固定资源预发布 `game-resources-v2`、Release ID `407394942`，既有标签与正式 APK 永不随目录更新移动。后续目录签署使用已发行公钥和已验证旧签名；累计 ID 不删除，保留旧 ZIP。

## 发布前

1. 功能与来源锁分别提交推送、独立审阅；使用干净独立检出生产并重复校验。
2. 提交推送发布工具并独立审阅。工具所在提交在独立检出重新生产，固定完整提交、期望旧目录 SHA、精确下一序列及新证据目录。
3. 执行 `scripts/publish-resource-successor.ps1 -Commit <完整SHA> -ExpectedPreviousSha <旧目录SHA256> -NextSequence <旧序列加一> -EvidenceDirectory <任务证据目录的新子目录>`。

工具先匿名下载当前签名、完整分页资产，核生产公钥、固定 Release、不可移动标签、干净且已推送来源及候选元数据，然后才读取凭据。新 ZIP 先上传；再次获取完整快照，绑定真实资产 ID/摘要并保留累计 ID；旧签名作为签署历史传入既有签名 CLI。私钥由 DPAPI 在内存解密并从 stdin 传入，禁止写私钥文件或日志。

全部签署与生产公钥验证成功后，再次核旧 current 资产身份与标签；把旧目录同一个资产重命名为 `catalog-seq<序列>-<摘要前12位>.signed.json`，最后上传新 `catalog.signed.json`。短时目录不可查询时客户端保留本地安装内容。匿名最终检查核新目录原始字节、历史目录原始字节、累计新旧 ZIP 字节与完整分页绑定，不限制为首次发布的固定资产数。

独立审阅建议已落实：匿名验收下载并验签全部历史目录，核序列从1至当前无缺口、无重复且逐次满足后继规则；验证每个历史目录与完整公开资产快照的绑定，下载所有历史/当前 ZIP 比字节和摘要。预检候选准入也按100项分页构造，超过协议最大页数时拒绝。

## 中断或未知结果

证据目录只允许首次使用，所有文件拒绝覆盖。任何错误先匿名读取 Release 与完整资产快照，比较 `activation-intent.json` 的旧资产 ID、历史名、旧摘要与本地已签新摘要。禁止盲目重跑、重签、覆盖或删除资产。若已重命名旧目录而新 current 未出现，仅在核验身份后上传该次已签文件完成原发行；若新 current 已存在，下载精确比较后继续验收。若身份不同，保留现场，先调查。该恢复动作不得产生新序列或移动标签。

## 客户端验收

用已安装正式 v0.4.0 的生产端点/公钥实际更新、激活，验证版本提示、旧存档和实际新功能。更新前后 SAF 导出同一自身进度并比摘要，显式仪器读取生产单例 active 身份及正式 APK 原始摘要。资源发布成功不等于客户端验收完成；正式手机验收仍由用户发布后安装检查。
