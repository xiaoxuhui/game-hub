# 自动检查与发行策略

- 日期：2026-10-12
- 状态：产品策略已确认；每日检测已部署，自动候选/资源发行仍按N13后续阶段实施。
- 用户补充：当前主要由开发者本人使用，避免每天增加正式Release造成版本混乱。

## 每日北京时间06:00

GitHub Actions在八仓启动检测，后续候选构建接在检测之后。无变化不重新生成产物；有变化则绑定完整源SHA、校验和及报告，保留Actions artifact（检测报告30天，候选保留期按容量制定）。未知/失败/兼容不通过明确阻塞，不创建正式版本。

Artifacts并不是公开Release；私有技能库产物保持私有。Actions产物下载可能需要GitHub登录，不能把候选artifact URL当成现有大厅面向所有用户的匿名更新接口。

## 子游戏局部更新

满足双向存档兼容及其余门禁的资源，未来自动发行到已存在的game-resources-v1/v2签名通道：复用原Release对象，追加不可变ZIP及递增签名目录，不每天新建Release或语义版本标签。目录sequence/contentCode持续递增、保留历史ZIP/旧目录及固定标签，不将资源通道设置为正式latest。

大厅已安装用户通过现有资源更新检查获取目录变化；候选构建并不等于资源已签名发行。当前仍缺自动候选/迁移及隔离签名端，规范发布通道不可宣称已无人值守接通。

## 正式版本

大厅APK和各独立游戏按明确的版本交付计划集中发行，归并更新说明及兼容报告；不以每日巡检次数驱动正式Release数量。版本号/证书/包内容及升级验收通过后才能切不可移动的正式标签，避免同版本换字节或移动标签。mini-app-harness按技能里程碑保存版本归档，仍为私有源库。

如后续需要在APP直接安装每天的原生APK测试候选，应另设计显式开发通道和可匿名下载的固定预发布入口，保留来源/签名/递增版本号校验，固定预发布对象可复用；当前正式APK的latest检查不自动切到测试候选。本轮未创建该通道。
