# 存档格式与升级兼容规范

- 版本：1.0，2026-10-12
- 状态：设计规范；现有游戏逐项接入待办，尚不是已实现的存储协议。
- 适用：大厅资源更新、独立网页/独立 APK 升级和回退。

## 1. 三个独立版本

游戏功能版本、大厅资源 contentCode、存档 schemaVersion 各自管理。改变可持久化的数据含义、结构或 reader 所需能力时，提升存档版本或显式新增必需 feature；不能因为 JSON 外形相同就沿用旧能力声明。APK versionCode、资源 contentCode、目录 sequence 只增不减。

新格式建议统一外层声明：format、gameId、schemaVersion、writerVersion、requiredFeatures、payload。每游戏发布合同声明 readSchemas、writeSchema、requiredHostCapabilities、migrationId、rollbackPolicy、测试夹具摘要。禁止接受未来未知 schema 后覆盖原数据。此设计不直接给当前 v1/v2 签名目录加字段；目录严格 reader 的协议演进要另做新通道/新大厅，并保持旧通道。

## 2. 升级合同

- 升级能力：新版读取已支持的历史数据并保留含义；必要时通过显式纯迁移函数转换，不偷偷降级数学语义。
- 回退能力：新格式不保证旧 reader 能读取。只有实测无损双写或无损逆迁移，才声明“可继续读写回退”。
- 不具备逆迁移时，允许“恢复升级前检查点”：保留新版数据及可导出副本，明确旧版只恢复检查点之前的进度。没有检查点不能自动切回旧 reader。
- 所有版本均保留旧导入格式 reader，直到明确弃用周期、导出工具及迁移路径已有验证；建议至少覆盖全部已发行格式，规模增大后再制定保留周期。
- 用户明确选择后才允许有损导出兼容副本，显示丢失哪些功能；不能覆盖完整原档。自动发布禁止用删字段、限制功能或改变规则来伪造兼容。

## 3. 迁移事务与备份

先校验原档并保存原始字节、摘要、来源资源版本和 schema；在新命名空间复制并迁移，验证领域不变量和导入导出往返；最后提交一个原子指针，使新资源与新 schema 同时生效。失败、中止、存储额度不足则不切换指针，旧资源与原档仍可用。迁移可重复执行，不产生重复记录。备份只留用户设备，默认不上传云端。

这需要具备事务/检查点能力的存储适配层：浏览器 IndexedDB 或等价双槽指针设计；仅多次 localStorage.setItem 不能当作跨键事务。游戏运行会话固定资源版本，退出游戏后才激活。浏览器缓存切换与 Android 资源激活也要遵守同一数据合同。

现有四游戏共享 origin，动态游戏各自 origin；现有大厅恢复旧资源按钮并不自带存档快照。不能在当前实现上声称已有无损数据回退。先在独立适配层实现能力，并为Android资源指针与网页数据指针跨存储提交制定恢复状态机：准备/迁移验证/待激活/提交完成各状态持久化，启动时只选已完成且资源和schema匹配的组合，不能假定两套存储可同时原子提交；需要新的原生检查点接口时另发大厅版本。能在现有网页能力内实现的迁移可随资源包更新，通常不必下载整个 APK。

## 4. 发布门禁

必须在干净固定 SHA 候选运行以下矩阵，产物、夹具、报告绑定 SHA/摘要：

| 测试 | 要求 |
| --- | --- |
| 每个历史 schema → 新 reader | 含义保留，未知字段按格式规则保留，不清空 |
| 新功能保存 → 新 reader | 新功能恢复完整，导入导出往返一致 |
| 新保存 → 旧 reader | 实测能读写，或明确阻止并恢复检查点；不能称未知为兼容 |
| 迁移重复/中断/损坏/未来版本 | 不污染原档、不重复、可恢复，失败消息可操作 |
| 空间不足/断网/重启/并发会话 | 资源与数据指针一致，旧会话不写进新格式空间 |
| 实际设备/浏览器升级与回退 | 真实操作保存、退出、激活、重启及检查点恢复 |

机器门禁和维护者独立审阅归档后允许生产发行；仅类型检查、简单字段扫描或口头兼容声明不能放行。

## 5. 三游戏迁移路线

- EML：组合函数和 EML_COMPOSITION 纳入新 format/capability 声明；旧工作台先只读加载并迁移，原档保留。组合函数引用和结果树必须完整恢复，禁止丢弃组合定义。
- Lambda：历史 v2 保持可读，新 v3 paths 的手动归约会话保留完整；回退恢复旧 v2 检查点，新 v3 数据仍保留。删除 paths 的结果只能是明确有损的另存副本。
- 图灵：历史整数 maxSteps 保持可读；新 unlimited 采用新 schema/feature 声明，保留 null 的无限含义。回退恢复整数限制的旧检查点，不把 null 擅自替换成 1000000。

## 6. 工程规范接入

各子游戏在自身仓库维护 schema 文档、历史合成夹具、迁移及回退测试、发布兼容合同。大厅打包器只读固定来源与合同；签名端校验门禁报告并拒绝未知格式。共用开发 skill 引用这份规则或后续唯一真源，避免各项目复制后漂移。将规范接入 mini-app-harness 及实现三个游戏迁移另列阶段，先保留用户本地未提交 skill 改动。
