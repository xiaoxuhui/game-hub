## 3. 两个必须先处理的发现

### 3.1 conway 的锁漏了两个运行时文件（照原样追平会打出坏包）

`conway-life-game/index.html` 在 HEAD 引用了：

```
scripts/record-import.js
scripts/file-backup.js
```

而 `sources.lock.json` 的 `files` 数组里**没有这两个**。`bundle.mjs` 只复制 `files` 列出的文件，所以追平后包内页面会引用到不存在的脚本。

→ 追平必须同时把这两项加进 `files`（16 → 18 项）。这是本次最容易被漏掉的一步。

### 3.2 EML / turing 是构建产物，不能直接复制仓库里的 dist

- **EML**：`files` 只有 `dist/eml-workbench.html`。`bundle.mjs:127` 会先跑 `node scripts/build.mjs` 生成**自包含** html（本地已构建版本 105 KiB，`grep katex` 命中 0、无任何 `src=`/`href=` 外链）。仓库里已提交的 `dist/eml-workbench.html` 是 198 KiB 的**未自包含中间产物**，引用 `katex/katex.min.css` 与 22 个 katex 文件 —— 手工复制它会让公式全部失效。
- **turing**：`files` 用 `dist/**` 通配，但仓库里的 `dist/` 是空的，必须 `pnpm install --frozen-lockfile` + `typecheck` + `build:android` 才产出。

```
conway: revision → 3dc937a0e369a5ef5520cc3333225d333fd6d7a2
        version  → 0.17.0（不变）
        files    → 追加 "scripts/record-import.js", "scripts/file-backup.js"
eml:    revision → 5da3778ec8c6eff65108c88112df1f21bdbe7a56
        version  → 1.3.1
light:  revision → 6adff61adfddae5c2ee38f41b18934570dce3423
        version  → 1.2.1
turing: revision → cb2d33bac808372c21e845480275278de66ae2f0
        version  → 0.6.0
```

`version` 必须与目标提交的 `package.json` **完全一致** —— `bundle.mjs:125` 会比对，不一致直接抛 `Version mismatch`。注意是**目标提交**的版本，不是工作区文件的版本。

## 5. 为什么本机不能完成（BLOCKED 原因）

1. **没有资源签名私钥。** 全仓只搜到 4 个 `debug.keystore`（APK 调试签名，位于 `.build/…/sources/*/android/app/`），不是资源目录签名密钥。`publish-resource-successor.ps1:137` 用 `ProtectedData.Unprotect(..., CurrentUser)`，即 Windows DPAPI —— 私钥只在 Windows 当前用户下可解，本机（macOS）无解。
2. **只改锁不发布会造成脱钩。** APK 内固定 4 游戏资源变成新版本，而签名目录仍指向旧 `contentCode` / `archiveSha256`，客户端可能把目录当成「可回退更新」。
3. 因此**改锁、构建、签名、发布必须同一轮原子完成**，不能分两次提交。

这也是本条 `[BLOCKED]` 的唯一原因 —— 不是设计未定，也不是工作量问题。
