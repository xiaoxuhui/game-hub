# 浏览器版大厅：本地一键启动

- 日期：2026-10-21
- 范围：本机预览已**组装好**的浏览器版大厅；不涉及 Android 构建、资源签名与发行

## 组成

| 文件 | 作用 |
|---|---|
| `scripts/start-browser-hall.command` | 一键启动器：探测端口 → 未启动则后台启动 → 已启动则跳过 → 打开浏览器 |
| `<大厅目录>/serve.js` | 静态服务器（零依赖，只用 node 内置 `http` / `fs` / `path`） |

启动器**不含**静态服务器，只负责定位并拉起 `serve.js`。默认大厅目录为 `$HOME/WorkBuddy/game_hub_browser`，即组装产物目录（含 `index.html` 与 `games/`）。

## 使用

```bash
./scripts/start-browser-hall.command             # 双击运行，或命令行执行
PORT=4181 ./scripts/start-browser-hall.command   # 换端口
```

## 可覆盖的环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `GAME_HUB_BROWSER_ROOT` | `$HOME/WorkBuddy/game_hub_browser` | 已组装的大厅目录 |
| `GAME_HUB_SERVE_JS` | `$GAME_HUB_BROWSER_ROOT/serve.js` | 静态服务器脚本路径 |
| `PORT` | `4180` | 监听端口 |
| `NODE_BIN` | 自动探测（`node` → 托管路径） | node 可执行文件 |

## 已知陷阱：本机端口探活必须 `--noproxy '*'`

若 shell 里存在 `HTTP_PROXY` / `HTTPS_PROXY`（本机曾出现代理指向 `127.0.0.1:55082`），`curl` 对 `127.0.0.1` 也会走代理；代理返回 **502** 时 `curl -s -o /dev/null` 的退出码**仍是 0**，探活会被误判为"大厅已在运行"，脚本于是从不真正启动服务器。

因此启动器改为：

```bash
curl -s -o /dev/null --noproxy '*' --max-time 2 -w '%{http_code}' "http://127.0.0.1:${PORT}/"
# 判定 = 200 才算在运行
```

**任何针对本机端口的健康检查都应遵循同一规则。**

## 其他行为说明

- 端口被占用时，脚本判定大厅已在运行并直接开浏览器；要换端口用 `PORT`。
- 启动后最多等 15 秒；超时会打印手动排查命令并退出 1，不会假装成功。
- `nohup` 丢弃了服务输出；需要日志时改为前台运行 `node <大厅目录>/serve.js`。
- `serve.js` 的 `SERVE_ROOT` 默认指向大厅目录，也可单独用 `SERVE_ROOT=` 指定。
