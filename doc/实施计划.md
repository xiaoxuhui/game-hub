# 实施计划：离线四项目游戏大厅 APK

> 本文件保留原实施与发行历程；启动提醒与子游戏更新的后续任务见 [v0.3.0 实施计划](实施计划-v0.3.0.md)。本轮只完成新版规划与自我评审。

- **Status**: PENDING
- **Approved**: 2026-09-30 用户在对话中授权无人值守开发、阶段提交与推送，要求每阶段提交后独立审阅并存档；明确暂不发布
- **Type**: feature

## 目标与执行约束

交付一个离线 Android APK 工程，在原生大厅进入康威生命游戏、EML 计算台、光学游戏和图灵机实验台。四个来源由 `来源基线.md` 中的完整 SHA 固定。**全部构建，包括合集自身的构建、依赖安装和 Android 打包，都在独立检出目录进行**；四个原仓库仅做只读状态核对。新远端保持私有，阶段提交后立即推送并用 `git ls-remote --heads origin` 核实。不打标签、不创建 Release、不部署。

每个阶段先定义验收，再写测试和实现，跑针对性及相关检查，提交推送后从独立审核视角审阅该提交。审阅意见、修正与复验写入 `doc/阶段审阅记录.md`，通过后才进入下一阶段。UI 改动需在真实浏览器检查桌面与移动尺寸；Android 能力按自动化、模拟器、真机三类分别记录，没执行的不标 VERIFIED。

暂用应用名“游戏大厅”、包名 `com.xiaoxuhui.gamehub`、`minSdk 24`、几何图标。首版不自动迁移旧 APK 私有存档；仅根据现有导入/导出能力编写手动迁移说明。正式分发和签名策略留到未来发布阶段定稿。

## 状态规则

`PENDING` 表示未开工；`COMPLETE` 表示代码与提交完成但验证证据尚未记录；`VERIFIED` 仅在对应命令的实际输出和涉及 UI 的实际操作写入报告后使用。状态只能按该顺序推进。每阶段审阅中发现的问题先修复、再复验、再进入下一阶段。
