# 网页缓存安装合同

状态：PENDING；W2.2a实现前合同。内部安装器尚不注册SW、呈现离线按钮或授予实际受控游戏会话。

## 1. 下载与校验

签名封装在首次await前限制/复制；repository.begin负责真实新鲜签名、当前水位、fence/完整预算与proof原子预留。下载URL只从已签game的id/code/digest/文件path计算，严格匹配该origin/basePath；GET、mode=same-origin、credentials=omit、cache=no-store、redirect=error。不依赖GitHub运行凭据，不从文件内容猜测新增依赖。

网络Response必须status200、type=basic、redirected=false、url精确相同，MIME与清单一致；Content-Length只作有界传输声明，Content-Encoding下不能当作解码后原文件长度。实际流读累计不得超过签名file.bytes（单文件20MiB），结束长度与SHA256必须相同；拒绝空body/超长/短读/错SHA。读取错误取消reader且不返回半个文件。

写入新的canonical Response，Content-Type、CSP、nosniff、CORP/Referrer策略固定为已审规则，不继承服务器的任意弱响应头。Cache返回允许default/basic，但仍逐字节/hash/MIME检查；不接受opaque。每文件30秒有界下载，用户可取消；顺序写入确保只有本任务一个put在途，每个任务只写其fence唯一cacheName。

## 2. 完成证明与跨存储边界

缓存键仅精确文件URL和一个本应用保留marker URL，不接受查询别名/跨版本/额外键。marker最多1024字节UTF8，严格字段schemaVersion=1、id/contentCode/digest/fence/proofHash/manifestDigest；必须与本次安装身份一致。完成标记最后写入，但标记存在不等于完整。

写完全部文件和marker后，重读keys、marker及每个文件并复验；只有精确闭包才能调用repository.complete。完成提交再次验当前签名期限/水位/CAS，期间目录换代则保守失败重试。Cache和IDB没有共同事务，ready之后仍可能被浏览器回收；后续每次会话入场必须再检查完整闭包，缺失进入repair，不能在线偷偷补成混合会话。本片不代替该SW入场门禁。

## 3. 取消、控制与保留

内部control()返回已验证的稳定控制身份；安装前、各下载步骤及提交前须非空且与首次相同，变化即停止。测试注入的gate仅测组件，正式caller须由唯一大厅controller/script/scope/真实握手派生，不能从URL/用户设置提供“已受控”。

取消只中止本任务fetch/后续put并将staging变failed；完整/旧活动代不变。出错不释放预算、不清理任何其它cache，不把不确定的迟到写入当结束。进度回调异常隔离且不授予状态。跨实例/崩溃的旧fence回调不能完成新任务；本片无GC/重试复用fence。后续只有证明写入收束、无会话引用且真实枚举/屏障成立才可移除失败任务与proof、释放预算。

游戏存档数据库与文件不参与资源删除；存档存在不说明缓存完整，缓存被回收也不自动删除存档。正式固定公钥入口、真实SW、PWA与离线冷启动在后续切片分别验收。
