## 需求与边界

在 game-hub 的默认分支配置每日巡检，北京时间 09:17（UTC 01:17），允许手动补查。检查六个实际上游仓库，包含康威、EML、光学、图灵、阿贝尔、Lambda；本仓库示范不当作独立上游。动态游戏从 upstream-source.json 取原仓库基线，不能把大厅适配提交误作上游版本。

康威追踪默认主分支与正式 Release，不扫描 APK 分支或 Dependabot 分支。2026-10-11 只读查询存在 9 个远端分支；main 的完整 SHA 为 87027a69ff93cb517c262a5010c342b7ac32b7d6，与大厅资源基线一致。正式 Release 当前为 v0.17.0；标签提交与 main 不同不等于新资源版本。

本切片交付每日**检测报告**。检测到新版本或资源相关变化时明确标记待处理，不写“已更新”或自动推进已发行目录。自动生产候选与签名发行分列后续待办，当前不上传本地 DPAPI 私钥到 Actions，不执行未经审核的上游代码。

## 设计

- 读取现有 resource-sources.lock.json 及阿贝尔、Lambda、红绿三个动态适配的 upstream-source.json，生成六源基线，不复制一份会漂移的版本表。图灵仓库有图灵主游戏与红绿两名消费者，分别保留自己的完整 SHA 和输入路径；每条消费者差异独立查询，汇总至同一图灵报告。红绿的大厅适配版本不能作为图灵上游版本参与比较。
- GitHub REST 查询仓库默认分支、固定主分支提交、latest 正式 Release；以数字语义版本比较，报告新版、同版、版本落后或无法识别，不默认“最新版”。
- 主分支 SHA 变化时，先匹配每名消费者的固定输入（含红绿 doc/red-green-puzzle.html），再排除已知 Markdown 文档/CI/测试。其余变化标记需要审查，不能自动忽略新依赖；不是把 doc/** 一律忽略。API 比较最多提供 300 个文件，达到此数或历史分叉则标记未知并使任务失败。
- 已审固定来源可能领先默认分支（例如红绿采用 APK 分支中的固定提交）。只有 API 的 behind 与 merge-base 等于默认分支完整 SHA 都成立才报告 baseline-ahead-of-main；不报新版、不回退固定来源。diverged 仍未知并失败。
- 每源独立保留查询结果；网络、限流、缺失仓库/提交或畸形响应标记 unknown，整个任务失败。latest 的 404 仅表示尚无正式发布，不代表已是最新版。
- 报告 JSON 与 Actions summary 同时提供主分支完整 SHA、基线、Release 和分类。输出不能包含认证材料；上游字符串在 Markdown 中转义。
- Workflow contents: read，checkout 不保留凭据，仅将 GITHUB_TOKEN 给检测步骤；每日与手动任务互斥，10 分钟总超时，每请求 20 秒超时，报告即使失败也上传，保留 30 天。无需构建 APK、无需修改原仓库。
- GitHub schedule 可能延迟或丢弃；公开仓库无活动 60 天会自动禁用。维护者须关注失败通知及定期确认任务仍启用；本轮不以自动空提交掩盖该平台限制。

依据：[GitHub schedule 文档](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)。

## 验收用例

1. 康威 main 与基线相同、Release 同版：无新版本、无主分支变化；不扫描其他分支。
2. 主分支资源变化但未发布：标记资源变化待审，不能写已发布新版；仅文档变化单独说明。
3. 更高正式版本、相同版本、旧版本分别判定；畸形版本不当作最新。
4. 阿贝尔无 Release：明确 no-release；403/超时/提交404/畸形响应为 unknown 并失败。
5. 动态适配读取实际原仓库 SHA；六源全部检查，单源失败不吞掉其余报告。
6. 分叉/300文件截断/新增依赖/重命名资源均不能误报资源未变化。
7. 手动真实 Actions 运行生成可下载报告，定时表达式部署在默认分支。
