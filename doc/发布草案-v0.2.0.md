# v0.2.0 发布执行清单

## 给使用者的说明

游戏大厅将康威生命游戏、EML 计算台、光学游戏和图灵机实验台收进一个离线 Android APK。首页使用四个原应用图标，竖屏常规尺寸下四个入口同屏可见。游戏资源固定在 [来源基线](来源基线.md) 列出的四个完整 Git SHA；联网只在用户点“检查更新”后用于查询公开正式 Release、下载并核验新版 APK。

安装包名称必须为 `game-hub.apk`。安卓最低版本为 API 24（Android 7.0）；包名为 `com.xiaoxuhui.gamehub`，版本号为 `0.2.0`、`versionCode=2`。原版四个独立 APK 可并存，但各自私有存档不会自动迁入；[迁移说明](迁移说明.md)列出可手动导出的范围。此前调试签名 APK 不能直接覆盖为发行签名版，请先导出可迁移内容，再卸载调试版并安装正式包。

首次正式发行后，已安装正式签名版可在大厅点“检查更新”：应用只接受本仓库公开正式 Release 中固定名称的 APK，检查 Release 资产摘要、包名、版本递增和与当前应用相同的证书，再交给 Android 系统确认安装。当前私有仓库没有公开 Release，升级链路的真实下载和系统安装 UI 尚不能端到端验证。

源码以 [MIT](../LICENSE) 授权；四个固定游戏与 Android 运行依赖的归属和许可文本随 APK 提供，并见 [第三方许可清单](../THIRD_PARTY_NOTICES.md)。

## 发布门槛与操作草案

- [x] 用发行证书的 0.2.0→0.2.1 递增版本在 AOSP 模拟器覆盖安装，确认应用私有文件标记保留、四游戏入口和手动查询仍可用；[执行摘要](evidence/p7-release-signer-upgrade.txt)与[原始输出](evidence/p7-release-signer-raw/README.md)已归档。
- [ ] 发布后由用户在真机安装验收；记录四游戏文件导入导出、断网冷启动、旋转与实际游戏存档隔离/保留。首次发布说明必须声明这些检查尚未执行。
- [ ] 发布后尽快将 PKCS12 与可恢复口令安全备份到另一台设备或离线介质，并验证可恢复。用户明确接受先发布的风险；当前仅有同一台电脑两个 ACL 受限目录和 DPAPI 口令副本，机器损坏可能导致今后无法同证书升级。
- [ ] 独立审核最终源码提交和 [开源就绪度审计](开源就绪度审计.md)，确认发布前仍无阻塞。
- [ ] 对最终提交重新运行常规 CI、未签名 Release 候选 CI、资源及权限核验；在仓库外 `zipalign` 与 `apksigner` 签名，记录最终 Git SHA、APK SHA-256、证书 SHA-256 和大小。不得把密钥、口令或签名配置上传仓库或 CI。
- [ ] 发布决定确认后再使仓库公开、在**与最终候选一致的提交**创建 `v0.2.0` 标签，创建非预发布 GitHub Release；仅上传固定名称 `game-hub.apk`，在 Release 说明附 SHA-256、证书指纹、迁移限制和本草案的使用者说明。
- [ ] 以匿名网络访问该 Release 的 `latest` 元数据和 APK，核对 API 资产摘要与下载文件一致；在已安装正式签名版上实测大厅更新查询、下载、取消和系统安装流程。发现阻塞时停止分发并修复，不将未执行项写为通过。

本清单随首版发布执行。最终 APK 摘要只有最终源码提交确定并签名后才可填写在 Release 说明和测试报告的该次运行记录中；未执行的发布后检查保持未勾选。
