# 游戏大厅 v0.3.0：需求与测试用例

- 日期：2026-10-03（Asia/Shanghai）
- 状态：规划草案；本轮仅完成文档、自我评审和批改，不实施代码或发布。
- 基线：已发布 v0.2.0；发行源码 `74216c3fba62faed3f92fb5daa8e3526ba35f866`。规划开始时大厅 HEAD 为 `c84212bf1837a886be3e283a23c1b7221504f020`。
- 配套：[设计](设计文档-v0.3.0.md)、[实施计划](实施计划-v0.3.0.md)。

## 1. 目标与用户要求

用户希望每个子游戏可以独立自动更新，不必为网页资源变化下载整个大厅 APK；大厅或子游戏有新版本时，在打开 APP 后获得自动提醒。本版规划在现有离线四游戏基础上增加启动检查、统一提醒和独立资源更新。

用户需先安装一次支持本机制的新版大厅 APK。以后 HTML、JavaScript、CSS、图片、关卡与 Worker 等受支持网页资源通过单游戏资源包更新；原生大厅、Android 权限、原生桥能力、信任公钥等变化仍通过 APK 升级。子游戏更新不安装其独立 APK，也不从仓库浮动分支直接执行代码。

## 2. 默认产品行为

| 项目 | 默认方案 |
|---|---|
| 打开 APP | 本地大厅立即可用；网络检查在后台线程异步执行 |
| 检查对象 | 最新正式大厅 APK，以及经过发行签名的子游戏资源目录 |
| 自动提醒 | 大厅顶部更新提示条和对应游戏卡片标记；不自动弹出安装窗口 |
| 子游戏下载 | 默认开启，仅在已验证、非计费的 Wi-Fi 网络下载；可关闭 |
| 移动网络 | 自动检查少量元数据；下载资源需用户主动确认大小，或显式开启移动网络自动下载 |
| 资源生效 | 下载并校验后等待该游戏无活动会话，下一次进入时使用完整新版 |
| 大厅升级 | 展示更新说明，用户点击后下载 APK 并确认系统安装 |
| 无网络 | 已有游戏照常运行；检查失败与“已是最新”明确区分 |

这些是本次规划采用的默认值，可在开发前按用户意见调整。APP 关闭期间不轮询，不申请通知权限，不承诺后台推送。进入后台再回来属于同一进程会话，避免频繁重复提醒；长时间离开后按设计的检查间隔重查。

## 3. 功能需求

### R10 启动检查与统一提醒

- 每次进程冷启动自动发起一轮检查；同一进程前台会话只保留一个检查任务。旋转、文件选择器和系统安装返回不视为新的启动。
- 后台超过 30 分钟后回到前台，可发起新检查；短时切换保留结果。手动“检查更新”可绕过普通间隔，但须遵守服务端限流。
- 首屏不等待网络。即使用户已进入游戏，检查可继续；结果留在大厅，回到大厅时可见，不打断当前游戏。
- 统一提示“大厅有新版”“N 个游戏可更新 / 正在下载 / 已准备好 / 本次已更新”；标注最后成功检查时间。若只有一条通道成功，另一条必须显示独立状态。
- 已发现且尚未处理的更新持续显示；用户关闭详细弹窗不等于忽略版本。自动提醒不每次重复弹窗，用户点提示条再看详情。

### R11 每个游戏独立更新

- 仅下载变化游戏的完整网页资源 ZIP；不下载整个大厅 APK，不做首版逐文件差分。
- 游戏按固定 ID 管理，仅允许 `conway`、`eml`、`light`、`turing`；版本名称供展示，独立递增的资源编号决定升级顺序。
- 大厅展示实际使用的版本、源 SHA 与“内置 / 已下载”来源；另列待生效版本，不能把远端版本当成本地已安装。
- 某游戏失败不阻止其他兼容游戏更新；每游戏串行安装，整应用同时仅下载一个资源包。
- 下载可取消；断网、空间不足、校验失败不改变当前版本。取消仅取消本次任务，明确保留自动更新设置，下一轮可能重试。

### R12 下载控制与体验

- 设置提供“自动更新子游戏”（默认开）与“允许移动网络自动下载”（默认关），设置持久保存；启动自动提醒仍保留。
- 在游戏运行中只检查元数据，不自动下载资源；用户回到大厅后按设置排队。手动下载也只在大厅启动。
- 进度显示游戏名、已下载/总大小及取消操作；用户进入游戏或 APP 退后台后停止下载并删除不完整临时文件，后续从头下载，不宣称断点续传。
- Wi-Fi 转为计费网络时按设置暂停并清理未完成文件；完整已验证候选可保留。每轮自动失败不无限重试。

### R13 信任与兼容

- APK 检查沿用现有包名、版本、SHA-256、已安装证书校验与系统安装确认。
- 资源仅来自固定大厅仓库的专用资源通道，目录经 APK 内置公钥验证发行签名；摘要不能代替发行签名。
- 每个资源声明最低/最高大厅 `versionCode`、资源协议和存档兼容标识。不满足任一条件时拒绝安装并提示原因；需要新版大厅时优先引导升级 APK。
- v0.3.0 只接受与当前游戏存档格式兼容、可由旧资源继续读写的更新。不支持仅靠自动迁移后再回退；不能验证双向兼容的版本不进入自动资源通道。
- 不下载或动态加载 dex、JAR、原生库；原生桥仅暴露给校验后的受信任网页，保持现有外网与路径限制。

### R14 离线、切换与恢复

- APK 始终带四个离线基准游戏；已激活资源放入应用私有持久目录，不能依赖易被清理的下载缓存。
- 更新生效以完整版本为单位；网页及其资源、Worker、关卡页在一次游戏会话中绑定同一版本。
- 保持原 HTTPS origin 和入口 URL，更新不清理 WebView 存档。四游戏仍共享 origin，不宣称浏览器级隔离。
- 新资源入口或必需文件加载失败时停止该会话，显示恢复入口；可在兼容性成立时切回上一版本或内置版本。不能自动识别所有玩法错误，不能承诺回退能撤销已发生的存档写入。
- 提供“恢复上一个版本 / 恢复内置版本”；只替换兼容资源，不清空存档。失败版本被本地隔离，不自动重新应用，直到更新资源编号或用户明确重试。

### R15 资源生产与发布

- 四个原仓库仍只读；每次资源候选记录仓库地址、完整 Git SHA、依赖锁、构建命令、资源摘要和许可，全部构建在独立检出目录。
- 源游戏的正式发布或提交可提示维护者生成候选，只有通过验证、审阅并由大厅发行流程签署的资源才对用户可见。原仓库仅发布独立 APK 不等于大厅资源已可更新。
- 资源通道不得影响现有 v0.2.0 客户端的最新正式 APK 查询；发布后分别核对两条通道。
- 资源与 APK 的签名私钥分开保管，APK 不含私钥或 GitHub token。新增资源密钥必须有异机可恢复备份；现有 APK 密钥异机备份仍为待办，用户之前接受的风险不自动扩展到新密钥。

## 4. 验收用例（全部待执行）

| 编号 | 条件或操作 | 期望结果 |
|---|---|---|
| U22 | 冷启动，网络响应延迟或超时 | 大厅与四游戏先可用；检查异步，无网络等待遮罩 |
| U23 | 大厅与两个游戏同时有新版 | 一条汇总提醒，详情各列版本、大小、动作；游戏卡片有标记 |
| U24 | 旋转、文件选择返回、短暂后台切换 | 不创建重复请求、下载或提醒；超过 30 分钟回前台才重查 |
| U25 | 无网络、403/429 限流、无资源通道、单通道失败 | 离线可玩，状态准确，按限流退避，不错误显示全局最新 |
| U26 | 仅光学资源编号增加 | 只下载光学 ZIP，大厅与其他三游戏版本及资源不变 |
| U27 | 非计费 Wi-Fi，自动更新开启 | 自动下载并校验；下一次进入游戏用新版，无 APK 安装窗口 |
| U28 | 移动网络、自动更新关闭、网络中途变化 | 遵守设置；手动下载明确大小；取消或暂停不替换当前资源 |
| U29 | 游戏运行中发现更新，或下载中进入游戏 | 当前会话固定旧版本；不打断游戏，不混用新旧脚本/Worker |
| U30 | 更新后断网并杀进程重开 | 四游戏可用，使用已激活版本与正确版本标识 |
| U31 | 篡改目录、签名、ZIP 或单文件；未知 keyId | 拒绝候选；不暴露原生桥给未经验证的内容 |
| U32 | ZIP 包含逃逸、绝对路径、重复路径、超大或缺失文件 | 安全拒绝；应用私有目录之外没有写入，当前游戏完好 |
| U33 | 下载/解压/状态提交各阶段杀进程、空间不足 | 重启恢复一个完整有效版本；半成品不激活，清理不删活动资源 |
| U34 | 大厅或存档兼容范围不匹配 | 拒绝资源，给出先升级大厅或不支持更新的说明 |
| U35 | 升级、返回、重启、恢复旧资源 | 四游戏实际进度/草稿保留，未调用跨项目清空；验证双向存档兼容 |
| U36 | 候选入口故障、用户恢复旧版、同失败版再次检查 | 恢复兼容旧资源，问题编号不被自动重新应用，存档不声称回到过去 |
| U37 | 旧签名目录重放、同编号不同内容、新编号承载旧代码修复 | 拒绝目录降级和编号冲突；合法发行回退采用新编号且兼容 |
| U38 | 安装 v0.3.0 以后有大厅新版 | 自动提醒；用户点击后走现有同证书系统安装流程，存档与兼容资源保留 |
| U39 | 发布资源通道，旧 v0.2.0 检查最新 APK | 仍只获得正式 APK Release，不把资源 Release 误判为 APK 版本 |
| U40 | 同时点击检查/下载、双通道并发完成、后台销毁 | 单任务协调，无重复安装、失效 Activity 回调或占用永久不释放 |
| U41 | 新大厅内置资源比已下载资源新，或已下载资源不兼容 | 按编号与兼容性选择；不误降级，清楚展示实际版本 |
| U42 | 图灵机关卡页/Worker、四游戏原生导出桥在资源更新后操作 | 动态资源仍完整加载，桥约定不变，真实导入导出可用 |
| U43 | 大字体、矮屏、TalkBack 下出现多项提醒 | 四卡入口可达，提醒有可读状态，详情和取消可操作 |
| U44 | 两次独立构建资源包，检查四原仓库状态 | 文件内容/清单可重现；原仓库前后 SHA 与状态相同 |

## 5. 不在本版范围内

逐文件二进制差分、后台常驻推送、静默 APK 安装、任意第三方游戏、账号云存档、存档格式迁移、动态原生插件、自动发布未经验证的来源提交。用户关闭 APP 后的即时通知不属于“打开 APP 时提醒”。

## 6. 本轮交付边界

本轮只完成本文件、设计与实施计划，自我评审指出问题后修订并存档。v0.3.0 是计划目标，不代表已开发、测试或发布；不修改现有 APK 版本号、来源锁定或发行标签。未来实现仍遵守小步提交推送、每阶段提交后换审核视角、留存批改记录和带勾选框进度。
