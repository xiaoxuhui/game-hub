# N6 已发行大厅的兼容资源局部更新计划

- Status: PENDING
- Approved: 用户授权无人值守继续开发与发布，N5发行及提交后独立审阅已闭环。
- Type: feature / resource release

## 目标

在不更换已发布v0.4.0 APK的条件下，将自有配对示范从内容#1/version1.0.0更新为#2/version1.0.1。增加键盘操作的焦点连续性与提示，使用正式生产公钥/端点实际更新，并保留已经在任务AVD生成的1步进度。原四源/两新游戏源只读。

## 切片及文件

1. **示范兼容功能**：examples/memory-demo/app.js、index.html及实际浏览器验收。保留core.js存档schema、键memory-demo-state-v1、统一桥、入口和稳定origin。render可接收恢复焦点的牌索引；翻牌重建节点后保持未配对牌焦点，原牌配对禁用后选择下一可用牌，全部完成时聚焦重新开始。牌上方向键、Home/End只改变焦点；Tab、Enter、空格沿浏览器原生行为工作。页面提供实际按键提示，存档内容不增加焦点字段。
2. **固定来源与生产**：功能切片提交推送并独立审阅后，才能用完整来源SHA更新dynamic-sources.lock.json的revision/contentCode/version/说明；没有另建动态编号锁，已发布签名历史是不可复用编号的门禁。在同一独立检出生产与重复摘要验证，源树与编译输出均按现有严格生产入口核验。
3. **后续资源发布工具**：独立维护工具与公开操作手册。固定game-resources-v2 Release ID407394942/tag peeled4aac不移动；显式固定已推送新源码SHA、期望旧签名目录SHA和递增序列。匿名读取并用APK固定公钥验证当前完整签名历史/分页资产快照，验证新ZIP/来源/累计ID/编号/合同，再签署。
4. **正式发布与客户端验收**：新ZIP先上传且保留旧ZIP；签署后先复核后续规则，再把旧catalog按序列/摘要留为历史资产、固定catalog.signed.json最后发布。发生未知结果先只读检查，不能盲重签/覆盖；短时查询失败时客户端保留已安装资源。记录每一步公开资产ID/hash和完整历史，不以初次N5发布工具误用新mainSHA移动原tag。
