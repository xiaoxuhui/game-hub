# N10 更新检查修复需求与测试用例

- Status: COMPLETE（规划完成，尚未实现）
- 日期：2026-10-10；用户报告“都默认最新版，不管有没有更新”，沿用无人值守开发、逐阶段提交后独立审阅、发布及清理授权。

## 需求

当前大厅只查询自己的正式 APK 和两份签名资源目录，没有逐一查询原游戏正式发布。源仓库发布新版本与大厅可安装资源是两种状态，必须分别说明。只读实查：光学 1.2.0→1.2.1，图灵 0.5.0→0.5.1，Lambda 0.3.0→0.3.1；Abel latest 接口返回 404，不能推断为最新。

1. 启动自动检查和手动检查查询固定六个游戏仓库的正式 Release；逐游戏显示已安装版本、已发布版本、签名资源可用情况。
2. 有源版本但暂无资源明确显示“资源包待制作”；已有签名资源继续按现有自动下载/安全激活流程运行。查询失败、离线、限流、历史缓存只能表示未知或待检查。
3. 红绿变换和大厅示例按大厅签名资源查询，不拿其独立产品版本和图灵/大厅版本比较。源仓库仅提交代码而未正式发布，不能宣称有正式新版。
4. 修复成功检查后断网仍显示新鲜“最新版”，以及未验证当前版本 APK 资产就宣称最新的问题。查询需向服务器重新验证缓存。
5. 三个已落后游戏以正式标签完整 SHA 独立生产资源；保持原 APK 四来源基线、存档合同、签名公钥及原发布标签不可移动。交付大厅 0.4.1（versionCode 5），真实手机由用户发行后验收。

## 验收用例

| 编号 | 场景 | 预期/证据 |
|---|---|---|
| U01 | 当前实现查询请求记录 | 复现缺少六源查询，修复后固定端点实际收到请求 |
| U02 | 源 Release 较已安装及签名资源新 | 显示准确版本及资源包待制作，不显示最新、不下载源 APK |
| U03 | 源 404/超时/限流/不合法版本 | 该项未知，其他通道继续；不覆盖可信本地资源 |
| U04 | 200 ETag→304；无缓存304；手动检查 | 必须服务器重验证；无缓存304失败，缓存仅在服务器304时可复用 |
| U05 | 查询成功后断网；失败后旧结果 | 标为历史/待检查，不再宣称刚检查最新 |
| U06 | 与当前 APK 同版本但缺失/不合法资产 | 查询失败而不是最新版；旧版本有效正式发布显示准确比较 |
| U07 | 启动、手动、退避、离开游戏/大厅 | 无并发重复查询；源失败不阻塞资源，尊重独立退避及自动检查间隔 |
| U08 | 红绿/示例及未安装游戏 | 独立资源状态正确，不发生跨产品比较；未安装不显示已最新版 |
| U09 | 三资源重复生产、合同审计、浏览器交互 | 固定新 SHA、逐文件清单/ZIP 相同，关键玩法及存档兼容实际通过 |
| U10 | v1/v2 累积发行 | 原历史字节/标签不变，生产公钥验证，旧 APK 发现三更新 |
| U11 | 正式 0.4.0→0.4.1 覆盖与查询 | 同证书递增版本、真实存档保留，真实网络及更新/失败夹具准确提示 |
| U12 | 收尾 | 证据归档、审阅闭环、原仓状态保持，仅清理本轮绝对过程根 |

实际执行方式、数量及未测边界写入测试报告；未运行项目不能标 VERIFIED。
