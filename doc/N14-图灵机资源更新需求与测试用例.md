# N14 游戏导入导出盘点与图灵机手动恢复需求

- 状态：实施中
- 现行图灵机：0.6.0 / contentCode 3，已于 2026-10-26 发布；本轮处理启动恢复行为并盘点所有在册游戏的导入/导出入口。
- 图灵机来源：已发布适配源 `ec1b7a0a6b7504c0adb9e15688031be0c7ff0ff3`，包含上游 `ffca525f838101151c9e1a6a8c6cb8798aa7d936`。

## 需求

1. 游戏大厅打开图灵机时显示默认新会话，不自动载入上次缓存或受保护的项目。
2. 页面首次渲染、无操作退出、重开及空白状态不得覆盖已有存档；第一次实际编辑自动保存前，先把之前的完整项目原文存入保护历史。
3. 用户主动点击现有“导入项目”并选择文件时才载入该项目；无效文件、取消操作和冲突对话取消均不改变当前会话或原存档。
4. 已有 Max 完整项目及未知字段继续保留。旧 reader 的 `maxSteps` 镜像只允许用户主动关联与 Max 项目其他已知字段完全相同的独立基础有限原档；不从旧包装/缓存推断。没有此原档时不写镜像，但完整运行和完整项目导出仍可用。
5. 逐项盘点当前大厅全部在册游戏的导入/导出；对带用户创建或编辑数据但缺少相应能力的游戏直接补齐。无可保存用户数据的纯展示/演示游戏标注为不适用并说明理由。
6. 原始游戏仓库只读；资源构建在独立检出目录完成。只发布更新后的大厅游戏资源，不构建 APK；保留全部签名目录及 ZIP 历史。

## 验收用例

- U01：当前资源发布记录与签名清单均确认图灵机 0.6.0 / content3 已发布；上游 `ffca` 已包含在已发布源 `ec1b` 历史内，不重复发布同一内容。
- U02：全游戏清单逐项记录 ID、版本、数据持久化方式、导入、导出、启动恢复、覆盖保护及证据路径；不遗漏动态目录游戏。
- U03：Turing 启动只读检查存档，不将其应用到新页面；新会话画面为默认项目，旧完整项目字节保持不变。
- U04：无操作退出/重开、首次默认渲染和无变化操作不写旧存档；第一次实际编辑保存前先将旧完整原文收入保护历史。
- U05：点击现有导入入口选择有效文件会应用它；取消、无效/超限文件不更改当前内容及旧存档。
- U06：新版完整 Max 状态与未知字段保留；仅当用户主动关联的基础有限原档除 `maxSteps` 外所有旧 reader 已知字段匹配时才可生成兼容视图；旧 C4 包装、普通历史、Max-only 文件均不能作为来源。
- U07：导入旧版修改后的兼容档时明确选择；应用旧版已知字段时保留完整档未知字段，恢复完整档时旧改动原文进入历史，取消不写入。
- U08：桌面和手机浏览器真实检查图灵机启动、导入、导出、备份管理及课程页，无页面错误。
- U09：对所有缺少导入/导出且拥有用户数据的游戏补齐相应入口与 schema 检查；导入无效/取消不覆盖数据，导出可读回。
- U10：定向、全量和相关上游测试通过；隔离目录两次候选逐文件 SHA 相同。
- U11：只更新实际修改的资源；发布后现有大厅可检查并获取；签名历史、未变化游戏 ZIP 摘要和完整匿名验证通过；不生成 APK。

## 明确边界

需求盘点以仓库锁定的全部在册游戏为范围，不从一个游戏推断另一个游戏的存档规则。已经发布的 Turing content3 不重新发布；content4 只用于承载经验证的手动恢复修复及确有必要的兼容更正。
