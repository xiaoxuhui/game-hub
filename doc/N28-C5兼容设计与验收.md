## 差异和旧 reader 能力

基线 HTML 使用旧 `LambdaSnapshot` reader，允许 v2/v3 存档，挑战 ID 仅限 1–5，level 索引仅限 0–4。目标上游仍输出 v2/v3 外壳，但加入 30 个挑战 ID、更多数值/多项式状态以及 `view.numberEncoding`、`decimalPlaces` 等新字段。旧 reader 会拒绝大于 5 的挑战 ID 或 level，且在校验后仅重建已知字段。因此仅复用新版完整存档格式会导致旧资源打不开。

## 已发行旧适配器的镜像关系

C5 不得把旧发布版本的 storage adapter 假设成纯 v3 reader。其 `getItem(hub-v3)` 会读取 `lambda-v2` 并与 `base(hub-v3)` 规范化比较；相同时保留 v3，不同时自动把 v2 编辑合并进 v3 并刷新 v2。其 checkpoint `removeItem` 会同时删除 v3 与 v2 checkpoint、将 ready.checkpoint 设为 false；首次恢复也可能因 ready/journal 状态写入多键。C5 Runtime 自己不得调用该旧 adapter；任何冲突判断前，须从底层 Storage 原始接口一次性拍摄所有候选键和适配器元数据，transaction 前再比较原文未变。

C5 写入 v3 projection 时，v2 键必须精确满足真实旧适配器的 `base(v3)` 关系，而不是另行猜测字段：对 v3 使用已发行 reader 解码/规范化，再按冻结的旧 `base` 规则生成 v2（版本2、无paths/函数source、新策略/方向旧默认值）；v2 再由同一旧 reader解码校验。先真实调用旧 content3 adapter 对镜像作冷读，断言读取不触发自动旧写。快照范围还包括 `lambda-lab-hub-mirror-ready-v3`、`lambda-lab-hub-journal-v3`、旧编辑/检查点archive及upgrade-backup。journal存在或readiness和键集不一致时先保留原始现场，不能预先触发旧 adapter 的recover。

## 数据分层

1. **完整新版当前档**：白名单键 `lambda-lab-hub-v4`；检查点 `lambda-lab-hub-checkpoint-v4`。保存经过目标 reader 验证的完整原文，包含全部 30 关进度和新版设置。
2. **content3 可读投影**：保留 `lambda-lab-hub-v3` / `lambda-lab-hub-checkpoint-v3`，使用已发行旧 reader 接受的 v2/v3 envelope；只包含旧字段及 1–5 关完成状态。新人关/数值字段可附在旧 reader 会忽略的扩展属性中，但它们的唯一权威副本仍为 v4 完整键。
3. **早期兼容键**：继续生成 `lambda-lab-v2` / `lambda-lab-checkpoint-v2` 的旧基础镜像。已发行 content3 适配器会把 `lambda-lab-hub-v3` 与 v2 键互相核对、合并旧写并同步重置；C5 每次读取/写入都必须独立校验这两套 current/checkpoint 原文、`mirror-ready` 状态和 v3 journal，不能假设 v3 是唯一旧写入口。首次迁移时保留 v1/v2 原始字节备份。
4. **新设置**：新版 `numberEncoding` / `decimalPlaces` 只存在于 v4 完整档；content3 可读投影删除未知视图字段，由旧 reader 使用其实际默认值。旧 reader 重存会丢弃未知扩展字段，但不触及 v4 完整键。C5 也维护 content3 适配器所需的 v3 ready flags，以便其能正常识别兼容镜像。

投影必须由已验证的完整 snapshot 生成，再通过固定的已发行 reader 实际解码。若当前关卡 >5，则旧投影置于自由模式、回到旧范围内的安全 level，同时保留当前 draft、函数、归约步数/原文及已完成的前五关；不能把第 6–30 关伪称为旧关卡，也不能把完整状态降级写回 v4。五关的精确含义须由基线旧 `presets` / reader fixtures 断言。

## 旧写冲突与用户选择

每次新版启动/读写先从底层Storage一次性读取v4/v3/v2 current与checkpoint原始字节、v3 mirror-ready flags、v3 journal、既有archive和upgrade-backup；任何旧adapter包装器调用前完成快照。分别用真实已发行content3 reader规范化v3/v2数据，再计算 `base(v3)` 并与实际v2关系核对。未知扩展属性被旧reader忽略，savedAt更新本身不算编辑。开始transaction前重新读快照内全部键并要求逐字节一致，否则中止并进入冲突选择。

若v3投影与v4推导结果一致，且v2逐字段等于实际旧adapter的 `base(v3)`、ready.flags匹配键存在状态、journal为空，则恢复v4。任一镜像差异、两镜像分歧、旧adapter archive发生变化、ready/journal显示中断或数据无效时，保留全体原文及元数据并展示可用候选：新版v4完整档、已验证的v3档、已验证的v2档；同一规范内容可合并为单个候选，不能按savedAt/lastWrite猜优先级。用户可选择一个或取消。选择候选前把所有未选原文逐字节归档；取消时所有键和值字节不变。

v4尚不存在时：只有一份有效的v3/v2来源且没有未完成journal/readiness异常时才自动迁移；若两份都在且满足旧adapter的 `base(v3)===v2` 才按旧adapter契约迁移；分歧则先显式选择并保留原文。checkpoint使用相同独立判定。若v4有checkpoint，而v3/v2 checkpoint均缺失且ready.checkpoint=false（旧adapter `removeItem` 墓碑），视为旧版明确清除：新版不得复活；归档v4完整checkpoint后向用户显示“保持已清除”或“恢复完整检查点”。若只有一代缺失或ready不匹配，属于镜像冲突，不推断为清除。

执行选择时使用 before/after journal 保护全键集合并写后回读验证。选择新版时先保存全部冲突双方后再刷新镜像；选择旧候选时先归档 v4，再以已选旧 reader 解码并通过新版 reader补默认值后建立 v4 档。若任何一步失败，展示当前键与原文而不盲目回滚并发写。

并发保证范围限于一个活动 Lambda 页面中的串行操作队列，以及可观测的同源 `storage` 事件：外部改写一经事件通知就使当前会话失效，停止后续写并提供双方已观察原文导出；每个journal写、镜像写前后核对快照且最终重新读取。测试须注入可控的外部旧writer交错，验证系统在事件/读回观察到冲突时fail-stop。浏览器 `localStorage` 不提供跨键原子事务或 compare-and-swap，无法保证另一页面/进程恰在最后一次比较后同时写入的无损合并；不支持多个旧新实例同时编辑，不能声称跨进程并发保护。用户应串行使用版本；可观察到的竞争会拒绝继续，未被平台暴露的瞬间竞争属于已知限制。

保存 v4、content3 镜像、旧基础镜像和状态记录通过有明确白名单的 before/after journal。任一步失败不得盲目覆盖并发写入；重启恢复只重放已验证的完整事务。上述只保证单活动页面串行顺序及可观测外部改写，不是跨页面/进程原子性。保护历史按原始字节去重，不能静默淘汰；配额不足时不写兼容视图并明确提示，完整档及原文导出仍可用。所有新状态键都仅限 Lambda 独占审计，APK 默认六键不变。

## 实施切片

- **A 需求/设计/旧 reader 基线**：把真实已发行 content3 reader 和目标 upstream commit 固定为 fixtures；先写旧 reader 对新挑战/进度拒绝的红测，再提交本合同和完整验收矩阵；提交后独立审阅。
- **B 投影与完整档核心**：实现旧 reader 投影、v4 完整快照、旧字段迁移/往返及旧 reader 实测；先测试后实现；只允许此切片变更核心适配模块。
- **C 冲突/事务保护**：覆盖content3适配器对v3/v2自动合并、两代镜像分歧、旧版检查点双键清除/ready墓碑、旧v3 journal中断、未知扩展剥离、取消、三类显式恢复、受控旧writer交错/storage事件fail-stop、备份和失败注入；独立分片提交/审阅。
- **D 资源集成**：从只读上游固定 commit 构建并生成来源证明；更新动态锁到 content4，适配准确 30 关 UI/完整导入导出；桌面/手机浏览器验证。
- **E 候选、生产和发行**：固定 producer commit 双次远端严格生产、候选 ZIP 完整审计、全量测试/CI；新鲜读取 v2 当前签名目录及序号，独立 READY 后仅发布 Lambda；匿名验证签名历史与全部累计 ZIP，独立终审。
- **F 文档闭环**：测试/发行报告、C5 计划状态、主分支记录和审阅意见；只保留当前任务范围，Lambda 外其它暂停项不动。
