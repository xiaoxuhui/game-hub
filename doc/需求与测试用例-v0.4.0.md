# v0.4.0 需求与测试用例：动态新增游戏

日期：2026-10-09（Asia/Shanghai）。Status: PENDING；Type: feature。

## 授权与范围

用户已授权在第二阶段发行后连续开发并发行第三阶段，不等待发布后的真机验收。v0.3.0 已发行并完成独立复审。本阶段先交付需求、设计、实施计划和自我评审，再按切片实现、提交推送并独立审核。

- 现有四游戏内置来源、URL、存档键、原生桥和v1资源通道保持兼容；四原仓库继续只读，构建仅在独立检出。
- 增加v2签名目录，支持无需改APK即可发现、下载和更新兼容网页游戏；需要新原生能力或不兼容存档合同的游戏提示升级大厅。
- 大厅打开时异步检查APK、四游戏v1及动态v2通道，单通道失败不阻塞离线游玩。
- 新游戏先提醒，首次下载必须用户主动选择；已经安装的动态游戏遵守现有自动更新/网络设置。
- 大厅首页保留四卡；未下载新游戏放在游戏目录中，成功安装后才加入首页。多个安装项可滚动、名称/实际版本/状态可访问。
- 支持移除动态游戏资源并保留存档，重新下载后恢复同一稳定origin数据；移除不自动触发重新安装。移除不能打断运行会话、文件选择或下载。
- 新游戏只支持网页、现有文件导入及统一`GameHubBridge.saveFile(name, content)`；不允许新增Android权限、原生执行文件、任意URL或公钥配置。
- 以大厅仓库自有最小配对示范游戏验证扩展；目录明确标为示范，下载可选，不修改四原游戏规则。Android APK不内置该示范的游戏资源。
- APK与资源签名密钥异机备份按用户2026-10-09授权延后，保持待办；真机TalkBack/厂商设备由用户发行后验证。

## 数据与边界

新游戏使用由合法ID派生的独立HTTPS origin，四原游戏保持旧origin以保留数据。普通移除仅删除可再下载的资源，不清空WebView存储；重新安装选择相同origin。卸载整个大厅仍可能丢失私有数据，文件导出是用户备份入口。

新游戏必须提供合法ID、名称、类别图标、完整来源SHA、递增内容编号、版本、入口、完整文件清单、许可、资源/桥版本、存档合同与大厅兼容区间。本轮类别图标用大厅内置图标，未知类别采用通用图标，不下载或解码任意远程图像。

累计最多16个动态ID；目录保留历史ID及高水位，退役用available=false，不通过删除记录撤销反重放保护。累计资源预算与v1共享300MiB，实际字节及空闲保留量仍受既有安全限制；存档不计入可回收资源，也不自动删除。
