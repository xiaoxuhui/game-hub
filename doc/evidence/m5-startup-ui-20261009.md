- onStop 取消订阅和更新详情对话框；普通退后台停止下载，旋转保留应用门禁与工作线程。onDestroy 释放游戏会话，不额外撤销旋转保留的下载。
- 进入游戏先取消下载，回大厅才允许继续排队。进度变化只更新详情里的进度文本，避免每个百分比重建设置控件和焦点。
- 离线未成功检查显示“未检查：离线”，不显示已是最新；已有成功状态保留此前检查时间。

## 797eac9 复审后的保存桥批改

- 原三项主路径经独立复审已修，但发现保存桥会先回 `true`、再因旧 Activity 停止而丢弃 UI 请求，受理回执与实际行为不一致。
- 新增 `UiRequestAcceptance`：网页线程等待主线程实际受理结果；还在队列里的请求超时可取消，后续 UI 调度不得再执行。主线程已开始受理的请求必须等待真实回执，不能超时回 `false` 却又打开窗口。`true` 仅表示系统保存请求被受理，文件写入成功仍由系统结果回调报告。
- `activityStarted` 改为线程可见；停止的 Activity 在桥入口直接返回 `false`。主线程再次检查存活、前台与外部 pending；启动 SAF 失败明确回 `false` 并报告失败。排队超时也给出前台可见重试提示。
- JVM 并发负例覆盖队列超时后晚调度不执行、受理/拒绝实际回执、执行中跨过排队预算仍等待真实结果。
- 新增实际 Activity 停止后调用生产桥的设备测试，断言返回 `false` 且没有建立待保存数据。反射只用于获取真实私有桥实例，不替换生产控制流；真实文件选择/文件写入/旋转存档流程仍待 M6。
- 前次三项批改实际 JVM XML 为 43 项、失败/错误 0；不是以 Gradle 任务数充当测试数。
- 保存桥最终批改 JVM 46 项、失败/错误 0；设备生命周期 5 项全部通过，`BUILD SUCCESSFUL`，2 分 2 秒。日志见 `m5-save-acceptance-final-tests.txt`；旧 6 项包括偏好订阅，新 5 项为实际 Activity 生命周期类，数量口径不同，不表示删减失败用例。
