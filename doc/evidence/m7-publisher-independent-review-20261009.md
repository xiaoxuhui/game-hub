## 阻塞项

1. **[P1] `$Commit` 未与已审源码和远端 tag 绑定（第 1、3、20、34、63–69 行）。** 参数接受任意字符串；脚本没有验证它是 40 位完整 SHA、等于固定独立检出 `HEAD`、已推送到目标仓库。若 `v0.3.0` 或 `game-resources-v1` 标签已存在，GitHub 不会因 Release 的 `target_commitish` 或 body 自动移动旧 tag；重试可把 `$Commit` 写成与真实 tag、APK 源码不同的值。复现思路：向只读审查用的参数传另一个提交号，观察所有本地门禁仍可继续；对于已存在 tag，API 返回的 tag 目标未被比较。修法：在任何远端写入前验证完整 SHA、固定检出 `HEAD`、干净工作树、远端已存在该提交；新建或复用 Release 时查询 tag ref，剥离注释标签并要求目标严格等于 `$Commit`，同时核对现有 Release 的 repo/tag/目标。
2. **[P1] APK 可以是任意现存文件，现有公开 Release 也可直接新增资产（第 62–68 行）。** `$Apk` 只经存在性检查；脚本没有要求其为已审独立候选、预期 SHA、`com.xiaoxuhui.gamehub`、`0.3.0/code3` 和发行证书。错误文件可被上传为正式 `game-hub.apk`，body 的 SHA 只是对错误文件重新计算。另若已存在 `draft=false`、无同名资产的 Release，`Add-Asset` 会先把新 APK 放到公开页面，不满足“draft 上传后公开”。修法：在上传前校对固定的预审候选绝对路径及 SHA、APK 包名/版本/签名证书；仅允许空的 draft 接受首次上传。已公开 Release 只允许幂等核对既有同名资产摘要、大小及 tag 目标，缺资产时拒绝并人工处理。
3. **[P1] 资源模式上传任意目录 ZIP，精确集合检查发生太晚（第 36、41–56 行）。** `Get-ChildItem *.zip` 会把混入的额外 ZIP 也上传到公开预发布；后续签名工具只验证目录所引用的四个资产，不能撤回额外的公开文件。即使四个正确 ZIP 的文件字节与 `games.unsigned.json` 不符，也是在上传之后才拒签。当前候选目录恰有四个 ZIP，这并不构成脚本自身的防护。复现思路：在隔离测试目录额外放一个 `unexpected.zip`，第 36 行会对其调用 `Add-Asset`。修法：远端写入前解析 unsigned manifest，精确验证四个预期名称的集合、无额外 ZIP、每个 ZIP 的长度和 SHA-256，再按预期集合上传。

## 已确认的安全行为与重试边界

- API 主机及仓库常量固定为 `xiaoxuhui/game-hub`；资源 tag 固定 `game-resources-v1` 且要求 `prerelease=true,draft=false`，正式 APK tag 固定 `v0.3.0` 且拒 `prerelease=true`。新建 APK Release 时为 draft，上传成功校验 digest/size 后才 PATCH 为公开；但上述已存在公开 Release 路径例外需修正。
- `Add-Asset` 不删除或覆盖资产，发现既有同名资产摘要/长度不符即拒绝；上传结果也核对状态、摘要与长度。POST 结果未知时重新 GET 可以核对已出现的资产。资源快照文件一旦存在即拒绝自动重签，这使未知结果需人工检查后继续，属于失败关闭；请给维护者明确的人工恢复步骤，避免盲删快照或重发目录。公开 APK 的 PATCH 结果未知时，也必须先核对 tag、body 和资产再决定是否重试。
- 资源私钥由仓库外 DPAPI 文件解密到内存，以标准输入交给签名进程；脚本没有将明文写文件，输出只显示公开摘要/URL。`finally` 移除 Authorization、清空可变密钥字节；PowerShell 字符串无法保证立即擦除，因而可表述为“不持久化明文”，不应表述成内存已安全抹除。未设置额外异机备份发行门禁，符合用户本轮授权。
