## 实现与前序批改

首页增加独立“游戏目录”入口，四内置卡仍单屏；动态游戏仅在有已安装/候选资源时加入首页，多个安装项按两列滚动。目录显示实际版本、候选、远端、退休、不兼容及历史提醒，提供用户主动安装、打开、移除保留存档、上版恢复、解除固定和明确重试。缺失状态时可根据可信历史重建目录，确认文案说明资源恢复为未安装、保留存档与水位、需要明确重试并手动重装。三类和通用图标为大厅内置矢量，不下载远程图像。

动态游戏 Activity 重建从本地可信元数据恢复相同 ID/origin，实际打开沿用普通缓存检查/会话/入口流程。系统字体与屏幕配置变化重新计算大厅布局，游戏 WebView 和文件流保留。首页、详情均展示新游戏启动检查状态；下载状态使用已验证的显示名。

前序 `0d85dba` 独立审阅无代码阻塞；要求区分旧失败日志与最终绿色日志，已在协调器证据文档明确，并归档审核原文。

## 最终实际验证

任务 AVD `emulator-5564`：**OK (17 tests)，49.503 秒**，3 项本切片 UI + 8 项动态协调 + 6 项旧协调回归。真实输出、同证书签名与构建日志归档 `n4-directory-ui`。

1. 真实原生节点点击目录安装实际固定来源示范 ZIP，完成后由首页普通卡片打开；不反射调用 `openGamePrepared`。写入示范真实进度，Activity 重建保持稳定独立 origin 和进度；通过原生移除确认移除资源，主动检查不自动重装；手动重新安装并打开后进度恢复。最后恢复任务模拟器此前的该示范存档。
2. 安装前实际测量四个卡片的全局可见矩形，四卡均完整可见，无需滚动；稳定截图已人工核验。实际系统 fontScale 1.6、Activity 请求横屏，配置核对通过。8 项展示夹具的目录滚动至末项，真正点击“打开”触发缺失资源错误，再点击“返回大厅”并滚动回顶部。仅多项布局使用合成数据；不据此声称 8 个真实资源包安装成功。字体/旋转设置在 finally 恢复。
3. 受控签名目录给出 minHost5 游戏，APP code4 实际显示不兼容说明，不出现安装按钮、不下载 ZIP。

测试专用反射只用于注入私有 store/coordinator 和多项展示夹具，生产安装不能选择任意信任根或 URL。HTTP 为受控流、资源签名为临时测试签名；普通打开链路、WebView、原生节点和真实固定来源 ZIP均执行。N5 仍须生产公钥、公网、干净提交候选及正式升级验证。

## 失败与批改记录

- 初始 2 项 UI 中普通安装/重建/移除重装通过，横屏未响应全局 user_rotation 设置。改为 Activity 实际请求横屏，仍检查真实 orientation 和 fontScale，不伪造 Configuration。
- 横屏第二轮已能滚动并点击末项打开、返回，但断言立即可见顶部入口失败。大字横屏下大厅保留滚动位置，改为实际滚回顶部再验收；未强制产品删除滚动状态。
- 首次截图捕捉了窗口过渡，稳定截图增加实际 UI 空闲和短暂动画等待后重新取得，原失败输出保留。最终 17 项均通过。
