# Lambda 配额保护修复：提交后审阅

- 审阅对象：`820f63c90523b96147c5aa453fd96bf6bd0519a5`。
- 用户现象：启动保护副本写入触发 `QuotaExceededError`，原提示阻止进入。
- 数据保护审阅：配额异常只进入只读路径，跳过 C5 迁移及其日志恢复；禁止写入、删除和自动恢复。手动导出枚举全部 Lambda 原始项和既有备份；预览需要用户明确点击，不自动替换任何存档。长历史的启动标记推迟到保护副本成功之后。
- 已检查的局限：只读模式不能保存新编辑，也不释放配额；导出超过 32 MiB 时需通过已有备份列表逐项导出。历史备份不会自动删除。用户需要显式处理配额后才可重新自动保存。
- 验证：目标 HTML 的所有内联脚本可解析；模拟配额耗尽、长历史和遗留日志时的导出与零删除零覆盖测试通过；Chrome 实际点击导出、只读进入和手动查看测试通过；手机尺寸正常存档及大备份回归通过；完整 Node 测试 316 项通过。
- 审阅发现：历史浏览器回归原本只接受旧错误标题；已调整为同时接受旧提示和新的配额提示。当前尚未在用户手机实机验证，不能声称已修复手机上的数据或保证所有存档完整。
- 结论：作为不删除用户数据的故障保护可进入发布准备；发布后应继续解决安全持久化和受用户控制的备份空间管理。
