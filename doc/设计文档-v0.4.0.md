# v0.4.0 设计：动态目录及稳定会话

日期：2026-10-09（Asia/Shanghai）。Status: PENDING；配套[需求](需求与测试用例-v0.4.0.md)、[实施计划](实施计划-v0.4.0.md)。

## D1 通道和协议

继续使用固定仓库xiaoxuhui/game-hub。正式latest只供APK；game-resources-v1继续提供现有四游戏，game-resources-v2作为独立预发布提供新增游戏。v0.3客户端不解析v2，不能把新目录塞进v1。v0.4协调器串行查询三通道，并独立记录错误、历史状态、检查时间和403/429退避。

v2沿用RSA3072 envelopeVersion1/keyId resources-20261008和原始UTF-8验签，payload schemaVersion2/channel game-hub-resources-v2。目录序号单调递增，有效期最多90天；资产ID/名称/大小/hash必须属于固定v2 Release。v2空目录允许首次部署；单游戏数据预算和完整文件清单复用v1规则。

动态ID为`[a-z][a-z0-9-]{0,31}`，不能使用四内置ID。目录累计最多16个动态ID，已知ID集合只能增加，退役记录保留且available=false。发行回退旧代码使用新内容编号，不能复用编号或让水位回退。

每项包含：id、displayName、iconKind、available、bridgeProtocol、ResourceGame既有来源/版本/编号/兼容区间/存档合同/入口/资产/完整文件列表。新游戏资源协议2、桥1、`<id>-dynamic-v1`存档合同、最低大厅code4。不支持的原生/存档能力只展示不兼容，不预约下载。本轮只用类别图标，未知iconKind显示通用图标。

## D2 复用安全核心

抽取共同签名与文件清单校验，v1解析的固定四ID/仓库/入口/合同约束保持原样。v2使用独立解析策略，不由用户配置端点、公钥或策略。

资源仓库复用GameResourceInstaller、AtomicFile状态、双签名信任日志、会话引用、取消/故障恢复和隔离逻辑。以受控策略参数支持动态ID、初始内容水位0及v2证明，默认构造仍是v1四游戏。动态状态位于独立私有根，不能把v2证明解释为v1。接受新目录前验证完整ID集合，高水位/移除墓碑不能因资源删除而丢失。

读取已验签目录的展示信息用于离线首页/目录；历史目录不能授权新下载，已激活资源的过期证明可用于离线加载。状态损坏时停止网络安装并显示明确修复路径，不静默重置可信水位。

两仓库共享300MiB资源容量预算和单队列预留，保持已有20MiB空闲保留量；任何回收只删除可验证私有资源，不跟随链接，不触及WebView数据或四原仓库。

## D3 origin与统一桥

四原游戏保留`https://appassets.androidplatform.net/assets/games/<id>/...`及原桥名。动态游戏使用派生主机`<id>.appassets.androidplatform.net`和相同资源路径结构；主机不能由目录提供任意字符串。GameContentResolver与导航/SW拦截只允许当前会话派生主机及签名完整文件列表，禁用网络加载并阻止跨游戏请求。

动态内容统一使用`GameHubBridge.saveFile(name, content)`，复用现有导出ViewModel/系统CREATE_DOCUMENT/后台写入/生命周期撤销。返回true仍仅代表已受理，不代表文件已写完；导入通过标准input[type=file]与系统选择器，不新增任意文件读写接口。桥仅绑定当前已验证会话，旧会话或后台请求拒绝。

缓存门禁针对当前origin已登记路径；不能清空localStorage/IndexedDB。动态源码禁止Service Worker/缓存代理及广泛存储清除，独立origin同时作为存档隔离和重装稳定身份。

## D4 首次安装、更新和移除

首页仅列四内置及已安装动态项；签名目录中尚未安装项出现在“发现新游戏”/游戏目录，展示大小与兼容性，由用户选择下载。首装不进入自动队列。已有动态资源才进入当前自动更新策略；移除清除active/ready/回滚资源选择，保留可信水位和WebView存档，并撤销自动安装资格。

下载、移除、恢复和APK流程使用同一UpdateTaskGate。游戏/外部选择器期间不允许本地移除；取消必须等连接与临时文件清理完成后释放占用。资源在安全进入时完整激活，打开会话期间不改变resolver。已安装退役游戏仍可离线打开，目录说明暂停提供更新。

## D5 资源生产及示范

增加独立动态来源/编号锁，固定完整提交、路径、版本和合同；不移动sources.lock.json。维护者从只读远端提交独立构建并签署，源仓库发布APK不会自动成为大厅资源。

自有示范游戏位于大厅仓库examples下，使用该仓库已提交的较早完整SHA生产资源，避免来源锁自引用。玩法为最小配对练习：6张牌、3对，逐次翻两张、匹配保留、不匹配可继续，明确胜局和重新开始；独立存档保存进度/胜局，JSON导入导出有格式校验。示范资源不进入APK内置assets。

首次发行用示范资源#1；另做兼容#2资源实际键盘操作改进，保留存档合同，用已安装正式v0.4完成在线局部更新验证，确认APK摘要及code4不变。该演示只改自有代码，四原仓库只读。
