# N10 更新检查修复设计

- Status: COMPLETE（设计，待独立审阅）
- 目标：把源发布提示、可信可安装资源和大厅 APK 状态分开，避免“无可安装资源”等价于“所有游戏最新”。

## 查询与状态

新增六项固定仓库注册表及源 Release 元数据客户端，仅允许注册表完整 HTTPS API latest 端点；元数据匿名、有字节预算、超时、取消及禁止跨域跳转。正式发布需校验 draft/prerelease、规范版本和仓库归属。源元数据仅用于提示，下载仍只能走现有大厅仓库资产 ID、签名目录及生产公钥，不扩大下载/执行信任。

源查询独立错误隔离；服务器限流遵守独立 upstream 通道退避；自动查询沿用 30 分钟间隔、前台大厅及单任务约束。固定六项逐一查询，单项错误不让其余源查询/资源通道跳过。重验证请求禁用本地 HTTP 缓存，带 Cache-Control: no-cache；仅真实服务器304可使用有界 ETag 内存缓存。

每项比对实际已安装（内置/激活）版本、可信签名资源最新版本和源正式版本：源更高但资源未跟进→待制作；签名资源更高→可安装/待生效；成功且同版本→注明已核对的正式版本；安装版本高于最新正式版本→显示双方数值；无安装→未安装。错误/离线只保留明确历史状态；红绿和示例只有大厅资源版本语义。即便当前没有更新也要能看到查到了哪个版本和查询时间。

版本比较只产生发布提示；可安装还必须满足当前可信目录的新鲜度、available、host/协议/storageContract兼容性及现有 eligible/pinned/quarantine 策略，过期/不兼容/未安装不得因版本相等显示可安装或已最新版。ready 只表示待生效，实际版本取 active，不用 ready 冒充已安装；不能安装必须给出具体原因，资源下载与激活沿用现有门禁。失败不能提升旧目录的新鲜度；旧候选保护和激活校验继续有效。Abel 实查 `/releases` 只有 prerelease=true 的0.1.2；`/latest` 404 显示“未找到正式发布，待检查”，已安装0.1.2仍如实保留。

大厅正式发布解析先完整验证可安装 APK 资产，再判断版本差异；保留当前下载预算、唯一资产、哈希和包名/证书校验。网络变化及错误不得把历史数据冒充新鲜结果。
