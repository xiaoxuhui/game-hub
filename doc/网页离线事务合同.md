# 网页离线事务合同

状态：PENDING；W2.1a代码前固定。账本只是内部协调组件，不是验签器、缓存完整证明或可运行授权。

## 1. 数据库边界

独立数据库`game-hub-web.resources.<basePath>`、版本1、单state store/key，不访问或迁移游戏saves数据库、localStorage。完整根形状固定schemaVersion/revision/nextFence/installations/sessions。不存在记录是首次；未知/损坏记录拒绝所有写操作并保留原数据。请求阻塞/版本变化/配额失败明确失败，无自动deleteDatabase或重建。

读改写在一个readwrite事务的get.onsuccess同步执行；不把验签、fetch、Cache或任何await放入事务。返回值只在transaction.oncomplete后成功。纯reducer复用同一字段/状态/预算校验，单个state记录让不同游戏/窗口的空间预留串行化。

## 2. 身份与预算

安装记录字段：id（游戏ID）、contentCode、digest、fence、cacheName、bytes、phase、proofHash。proofHash是上层验证完整签名原字节摘要；账本不接受该摘要本身作为签名已验证的证据。cacheName只能由账本根据basePath哈希与单调fence生成，不能外部指定。版本身份三元组唯一；fence全局单调增加，安全整数耗尽拒绝。

bytes为上层计算的完整文件及证明/完成标记保守预算，正安全整数；全部记录包含staging/ready/active/retained/failed/repair/deleting，均计入150MiB总额，始终留20MiB安全余量。取消/错误/崩溃不直接释放，只有完成可证明的专属缓存删除、同fence提交移除才释放。故障注入证明不能借并发或旧回调超预留。已存在同版本任务拒绝新建，不重复增加预算或复用fence。

## 3. 转移与会话

- begin创建staging、分配fence/缓存名并预留预算。
- complete仅同fence的staging及matching proofHash/完整清单摘要可变ready；上层须在此之前完成全部文件/完成标记验证，并在提交前重新验证新鲜目录。
- cancel仅staging→failed；迟到complete/cancel不得触及另一任务或变更失败记录。
- enter只允许ready/active，生成唯一会话引用并将该版本active；原active变retained，已打开会话保持旧完整身份。引用包括sessionId/clientId/controllerProtocol/id/contentCode/digest/fence，重名/错身份拒绝。这条内部转移不是对未受控页面授信，入口与SW需另外完成身份/完整校验。
- leave只移除精确sessionId/fence引用；未知或冻结客户端引用不按心跳/超时删除。恢复和BFCache使用原引用；首版无自动回收。
- missing只允许ready/active/retained→repair；不更改存档或删除引用。
- begin-delete仅failed/retained/repair，且账本无会话引用；上层还须给出同fence、完整客户端枚举/协议/阻断新入场的屏障凭证。active/ready/staging拒绝删除。未知枚举、可能冻结客户端、活动缓存或迟到写入未收束时禁止提供凭证。
- deleted仅同fence的deleting且明确cacheAbsent=true；移除记录后才释放预算。删除中崩溃保持deleting并拒绝运行；不能把部分缓存当完整旧代恢复。

所有事件未知字段/类型拒绝；错误不改变原state。持久证明的真实签名/固定公钥入口、Cache写入和每次运行完整性由后续W2.1b/W2.2实现并独立验收；本片不注册SW、不开放已保存状态。
